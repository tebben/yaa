## Git panel, diffs and annotations

The git panel is a built-in plugin that uses the `git` CLI through the core's git service.

**Changes**

- Lists changed files for the worktree as a flat list or a tree, grouped into staged and unstaged, with per-file and per-folder stage, unstage and discard.
- Clicking a file opens its diff as a tab in the editor area (Monaco diff editor). A single click opens a reusable preview tab, and a second click or an edit pins it.

**Annotations**

Annotations turn review into a loop with the agent.

1. In a diff or a normal editor tab, select lines and add a comment from the gutter or a key. It appears as an inline widget.
2. Each annotation stores the file, line range, side (old or new), a snippet of the surrounding code, the text, and a state (open, sent, resolved).
3. A review panel lists all annotations for the worktree. A key sends the open ones to the active chat as one structured message: file and lines, the snippet, and the comment.
4. When the agent edits the file, annotations are re-anchored by matching the stored snippet. When that fails, the annotation is marked stale instead of silently moving.

**Commit**

- A message box with stage-all, commit and a generate button. Generate sends the staged diff to a model and fills the message. Which model it uses and the prompt are settings (see Generated text in `05-agents-chat.md`).
- Pushing and creating a pull request live in the PR/MR plugin, not here.

The changes tree is part of the first version; a commit graph view is a later plugin.

## Pull and merge requests

A PR/MR plugin, built on the source-control connector (GitHub first), covers the path from a finished worktree to a merged change.

- **Create:** from the current worktree branch, with the target branch defaulting from project settings. Title and description are prefilled from the commits and can be generated by a model. The result opens in the browser or in the app.
- **Status:** a panel and a footer chip show the request state (draft, open, merged, closed), review state and mergeability, and the CI/CD checks with per-job status and links. The connector polls while the panel or chip is visible, with backoff; there are no webhooks for a local app.
- **Merge:** enabled when the connector reports it is allowed, using the project's merge method, with a confirmation step. After a merge the app offers to finish the worktree (remove it and delete the branch).
- **Surfacing:** the PR state also appears as a badge on the worktree in the left menu and as a column in the project overview.

GitLab implements the same interface, so this plugin does not change when it is added.

**Review comments:** reviewer comments on a pull request are pulled in through the connector and shown as annotations in the diff, marked as coming from the reviewer, so they can be sent to the agent the same way as your own.
